# Despliegue Debian con Docker Compose

**Preparación documentada; no desplegar públicamente sin autorización.** Requiere Debian con Docker y Compose, un dominio dirigido al VPS y puertos 80/443 disponibles. En una copia del repositorio, crea `secrets/` con permisos `0700`. Crea también `secrets/credential_keys` con una clave Fernet generada localmente (`python3 -c "from cryptography.fernet import Fernet; from pathlib import Path; Path('secrets/credential_keys').write_bytes(Fernet.generate_key()+b'\n')"` desde la raíz, con `umask 077` activado) y permisos `0600`; guárdala en un gestor de secretos y copia de seguridad cifrada, porque perderla impide descifrar las credenciales BYOK. Para rotarla, coloca la nueva clave en la primera línea y conserva las antiguas debajo hasta recifrar las credenciales. Crea `secrets/db_password` y `secrets/database_url` con permisos `0600`; el segundo contiene una URL `postgresql+psycopg://edustudio:CONTRASEÑA@db:5432/edustudio` con la misma contraseña, codificada para URL. Nunca añadas esos archivos a Git.

Copia `.env.example` a `.env` en la raíz y define `EDUSTUDIO_DOMAIN`. Desde `infra/`, ejecuta `docker compose --env-file ../.env -f compose.yaml config` para validar, luego `docker compose --env-file ../.env -f compose.yaml build`, `docker compose --env-file ../.env -f compose.yaml up -d db api`, `docker compose --env-file ../.env -f compose.yaml exec api alembic upgrade head` y finalmente `docker compose --env-file ../.env -f compose.yaml up -d`. Comprueba `/api/health` mediante HTTPS. Caddy obtiene y renueva certificados TLS automáticamente cuando DNS y puertos funcionan.

Los volúmenes `postgres_data`, `caddy_data` y `caddy_config` persisten datos y certificados. La base de datos y la API solo viven en la red interna. Planifica copia periódica cifrada del volumen o `pg_dump` y ensaya una restauración. Define responsable, calendario y retención antes de producción. Los logs actuales son los de Docker; el formato JSON estructurado queda pendiente de endurecimiento para producción. El registro de usuarios sigue abierto; limitarlo es necesario antes de un despliegue institucional abierto.
